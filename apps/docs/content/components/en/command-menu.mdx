## Installation [#installation]

<Install />

Import it from `owsem-ui/owsem`: Command Menu is an Owsem component, so it has its own entry. In the
registry it is the `command-menu` item.

## Usage [#usage]

```tsx
import { CommandMenu } from "owsem-ui/owsem";

const groups = [
  { value: "Pages", items: [{ value: "dashboard", label: "Dashboard", run: openDashboard }] },
  { value: "Actions", items: [{ value: "new", label: "New document", keys: "⌘N", run: create }] },
];

// ⌘K or Ctrl K opens it from anywhere; shortcut={false} turns that off.
export function Commands() {
  return (
    <CommandMenu.Root items={groups}>
      <CommandMenu.Trigger>
        Search…
        <CommandMenu.Shortcut aria-hidden>⌘K</CommandMenu.Shortcut>
      </CommandMenu.Trigger>
      <CommandMenu.Popup aria-label="Commands">
        <CommandMenu.Input aria-label="Search commands" placeholder="Search…" />
        <CommandMenu.Empty>No results</CommandMenu.Empty>
        <CommandMenu.List>
          {(group) => (
            <CommandMenu.Group key={group.value} items={group.items}>
              <CommandMenu.GroupLabel>{group.value}</CommandMenu.GroupLabel>
              <CommandMenu.Collection>
                {(item) => (
                  <CommandMenu.Item key={item.value} value={item} onClick={item.run}>
                    <CommandMenu.ItemLabel>{item.label}</CommandMenu.ItemLabel>
                    {item.keys && <CommandMenu.Shortcut>{item.keys}</CommandMenu.Shortcut>}
                  </CommandMenu.Item>
                )}
              </CommandMenu.Collection>
            </CommandMenu.Group>
          )}
        </CommandMenu.List>
      </CommandMenu.Popup>
    </CommandMenu.Root>
  );
}
```

Command Menu is a dialog with a search field: a palette that runs a command or opens a page from the
keyboard. It is a Base UI Dialog with an Autocomplete inside. Typing filters the list: the Autocomplete
matches each item's label, and a group without matches goes. The first match is always highlighted, so
Enter runs it right away. Pass `filteredItems` to rank the results yourself, as the docs search does
with fuzzy matching.

One highlight marks the item that Enter runs. It is Glide, from `owsem-ui/core`: whenever the arrows,
the pointer, or the query move Base UI's highlight, it slides there by transform alone. Focus stays in
the field; the list follows through `aria-activedescendant`.

Items sit in groups, each named by a GroupLabel. An item lays its parts out in one row: ItemIcon,
ItemLabel, ItemDescription, which gives way first when the row runs short, and a Shortcut of small
keycaps at the end. A long list scrolls, and an edge fades while there is more that way.

⌘K or Ctrl K opens and closes the menu from anywhere in the document, unless something else handled the
key first (`preventDefault`). Set `shortcut` to another key, or to `false` for a second menu on the
page: the demos here use `false`, because the docs search already owns ⌘K.

## Anatomy [#anatomy]

<InspectButton />

Root renders no element, so Inspect outlines the box that holds the Trigger and its panel. The
panel's portal holds `div.ow-command-menu__backdrop` (`data-blur` with `backdrop="blur"`), then
`div.ow-command-menu__viewport` around the popup.

| Part | Element | Notes |
| --- | --- | --- |
| <Part name="Root" /> | none | Dialog.Root, the list's items and query, and the `shortcut` |
| <Part name="Trigger" /> | `button.ow-command-menu__trigger` | Dialog.Trigger, a flat field with a search icon (`svg.ow-command-menu__icon`) and `aria-keyshortcuts` |
| <Part name="Popup" /> | `div.ow-command-menu__popup` | A `dialog`: Dialog.Popup, with Autocomplete.Root inside |
| <Part name="Input" /> | `input.ow-command-menu__input` | A `combobox`: Autocomplete.Input, after a search icon, in the search row `div.ow-command-menu__field` |
| <Part name="List" /> | `div.ow-command-menu__list` | A `listbox`: Autocomplete.List; it scrolls, and holds the Glide highlight (`span.ow-glide`) |
| Group | `div.ow-command-menu__group` | A `group`: Autocomplete.Group; `items` feeds the Collection inside it |
| <Part name="GroupLabel" /> | `div.ow-command-menu__group-label` | Labels its group |
| Collection | none | Renders the filtered items, one function call each |
| <Part name="Item" /> | `div.ow-command-menu__item` | An `option`: Autocomplete.Item, with `closeOnClick` |
| ItemIcon | `span.ow-command-menu__item-icon` | Decorative (`aria-hidden`), the font size plus 2px |
| ItemLabel | `span.ow-command-menu__item-label` | One line |
| ItemDescription | `span.ow-command-menu__item-description` | Muted, on the same line; gives way first |
| <Part name="Shortcut" /> | `kbd.ow-kbd.ow-command-menu__shortcut` | A [Kbd](/en/kbd) keycap, at an item's end, in the Trigger, or in the Footer |
| Empty | `div.ow-command-menu__empty` | Shown when nothing matches, and announced politely |
| <Part name="Footer" /> | `div.ow-command-menu__footer` | Key hints, past a hairline |

Popup also renders a close button, `button.ow-command-menu__close`, hidden until it has focus: touch
screen readers have no Escape key. `closeLabel` names it.

## API reference [#api]

### CommandMenu.Root

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `Item[] \| Group[]` | | What the list shows; grouped items give the item type through their groups |
| `value`, `defaultValue` | `string` | `""` | The query |
| `onValueChange` | `(value, eventDetails) => void` | | Called as the query changes |
| `shortcut` | `string \| false` | `"k"` | The key that, with ⌘ or Ctrl, opens and closes the menu |
| `handle` | `createHandle()` | | Opens the menu from anywhere, such as a button outside it |

A handle from `CommandMenu.createHandle()` opens the menu from anywhere, as the search button in these
docs' dock does. Other props go to Base UI's [Dialog.Root](https://base-ui.com/react/components/dialog#api-reference), and the list props (`filteredItems`, `filter`, `limit`, and the like) to its [Autocomplete.Root](https://base-ui.com/react/components/autocomplete#api-reference).

### CommandMenu.Trigger

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Text and height: 13, 14, and 16px |
| `handle` | `createHandle()` | | Needed when it is outside Root |

#### Data attributes

| Data attribute | Present when |
| --- | --- |
| `data-size` | Always; the chosen size |

### CommandMenu.Popup

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | The text size of the panel |
| `backdrop` | `"dim" \| "blur"` | `"dim"` | The scrim over the page; `"blur"` also blurs the page under it |
| `container` | `HTMLElement` | `body` | Where the popup renders |
| `closeLabel` | `string` | `"Close"` | The close button's name, for touch screen readers |

#### Data attributes

| Data attribute | On | Present when |
| --- | --- | --- |
| `data-size` | Popup | Always; the chosen size |
| `data-blur` | Backdrop | `backdrop="blur"` |

Other props go to Base UI's [Dialog.Popup](https://base-ui.com/react/components/dialog#api-reference).

### CommandMenu.Item

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `onClick` | `(event) => void` | | Runs on a click, and on Enter while highlighted |
| `closeOnClick` | `boolean` | `true` | Closes the menu once it runs, unless `onClick` prevented the default |

Other props, `value` and `disabled` among them, go to Base UI's [Autocomplete.Item](https://base-ui.com/react/components/autocomplete#api-reference), and so do its data attributes.

Every text is yours to translate: the Input's label and placeholder, Empty, the group names, the
Footer, and `closeLabel`.

## Accessibility [#accessibility]

| Key | Action |
| --- | --- |
| ⌘K, Ctrl K | Opens the menu from anywhere, or closes it |
| Arrow Down, Arrow Up | Next or previous item, across groups |
| Enter | Runs the highlighted item |
| Escape | Closes the menu; focus goes back where it was |
| Tab | To the close button, shown while it has focus |

- By default the menu is a modal dialog: focus stays inside while it is open and returns when it
  closes, and the page's scroll is held without an `overflow` style.
- The field is a combobox whose `aria-activedescendant` is the highlighted item; each group is
  labelled by its GroupLabel, and disabled items have `aria-disabled`. Empty is a polite live region.
- The Trigger announces the shortcut with `aria-keyshortcuts`.
- In forced colors, the panel, the Trigger, and the keycaps keep an outline, and the highlight is a
  `Highlight` outline. With `prefers-contrast: more`, the Trigger gets a 1px edge in `--ow-edge` and the
  panel a ring in it. Right to left, the layout mirrors: the Popup renders in the body, so it takes its
  direction from Base UI's `DirectionProvider`.

## Theming [#theming]

Command Menu reads these theme tokens. The Popup renders in the body, outside your layout, so set
them on `:root`, or on the Popup itself through `className` or `style`.

<Tokens />

| Theme token | Purpose |
| --- | --- |
| `--ow-raised-bg` | The glass, at 80% over a blur of the page, and the opaque panel |
| `--ow-popup-shadow` | The panel's shadow |
| `--ow-backdrop` | The scrim over the page, which `backdrop="blur"` also blurs |
| `--ow-fg` | Text, and the lit item's icon; also the Trigger's tint, 6% (9% on hover), and the keycaps' 9% |
| `--ow-muted` | The Trigger's text, group names, descriptions, icons, keys, and disabled items |
| `--ow-focus` | The Trigger's ring |
| `--ow-hover` | The highlight (Glide) |
| `--ow-radius` | The panel's and the Trigger's corners; items, the close button, and Glide take it less 6px, and keys half |
| `--ow-line` | The hairlines under the search row and over the footer |

The scrim sits outside the Popup, so set `--ow-backdrop` on `:root`, where it dims every modal layer.
The panel is at most 560px wide: to change that, set the Popup's `inline-size` through `className` or
`style`, such as `min(100%, 720px)`. For an opaque panel, as the Solid example does, give it
`background-color: var(--ow-raised-bg)` and `backdrop-filter: none`.

<ForMode mode="isolated">

In isolated mode the values sit on each part's own root, the Trigger, the Popup, and the scrim, so a
value on `:root` does not reach them. Set yours on the part itself, as `commands.css` does with the
Popup's `className`.

</ForMode>

## Motion [#motion]

The panel opens and closes at once: a palette opened from the keyboard many times a day does not
animate. The highlight slides from item to item on the Glide spring. With `prefers-reduced-motion`,
the highlight fades instead of sliding; nothing else moves. With `prefers-reduced-transparency`, the
panel is opaque and the page is not blurred.
