## Installation [#installation]

<Install />

Import it from `owsem-ui/base`. In the registry it is the `tabs` item.

## Usage [#usage]

```tsx
import { Tabs } from "owsem-ui/base";

export function ProjectTabs() {
  return (
    <Tabs.Root defaultValue="overview">
      <Tabs.List aria-label="Project">
        <Tabs.Tab value="overview">Overview</Tabs.Tab>
        <Tabs.Tab value="activity">Activity</Tabs.Tab>
      </Tabs.List>
      <Tabs.Panel value="overview">The project at a glance.</Tabs.Panel>
      <Tabs.Panel value="activity">What happened lately.</Tabs.Panel>
    </Tabs.Root>
  );
}
```

Tabs show one panel at a time, picked from a row of tabs. The row is a flat well with no edge, and a
tinted key slides under the active tab, the same look and motion as Toggle Group: it stretches from
its leading edge toward the new tab, and settles without bouncing. You write four parts; the key
and the hover highlight draw themselves. Only a change from one tab to another slides.

## Anatomy [#anatomy]

<InspectButton />

Four parts are yours to write; the list draws the indicator.

| Part | Element | Notes |
| --- | --- | --- |
| <Part name="Root" /> | `div.ow-tabs` | Base UI's `Tabs.Root`: the list and the panels. Tokens set on it reach every part inside |
| <Part name="List" /> | `div.ow-tabs__list` | `role="tablist"`: the well. It draws the indicator and Glide's highlight, and scrolls sideways when the tabs do not fit |
| <Part name="Tab" /> | `button.ow-tabs__tab` | `role="tab"`, `aria-selected`. Its text is wrapped in `span.ow-tabs__label`, so a tab with only an icon is square |
| <Part name="Indicator" /> | `span.ow-tabs__indicator` | Decorative (`aria-hidden`); the list draws it |
| <Part name="Panel" /> | `div.ow-tabs__panel` | `role="tabpanel"`, labelled by its tab. No padding, so your content decides |

Base UI has a `Tabs.Indicator` of its own, which OwsemUI does not export: it places itself by
`translate`, which falls between pixels at a fractional zoom. This one rests where layout puts the
tab, on the same pixels.

## API reference [#api]

<BaseUiReference />

### Tabs.List

#### Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | Font size and padding of the tabs |

| Size | Font | Tab | Well |
| --- | --- | --- | --- |
| `sm` | 13px | 24px | 32px |
| `md` | 14px | 32px | 40px |
| `lg` | 16px | 40px | 48px |

The well is as tall as a Button of its size, and the tabs sit 4px inside it. An icon is the font size plus 2px.

#### Data attributes

| Data attribute | Present when |
| --- | --- |
| `data-size` | Always: `sm`, `md`, or `lg` |

### Tabs.Tab

#### Data attributes

| Data attribute | Present when |
| --- | --- |
| `data-held` | Held down (on the indicator too, while that tab is the active one) |

A tab's text is wrapped in a label, so a tab with only an icon is square.

## Accessibility [#accessibility]

The list is one tab stop.

| Key | Action |
| --- | --- |
| Tab, Shift Tab | Into the list, then on to the panel |
| Arrow Right, Arrow Left | The next or previous tab, reversed right to left. It loops and scrolls the tab into view |
| Arrow Down, Arrow Up | The same, when vertical |
| Home, End | The first or last tab |
| Enter, Space | Pick the focused tab |

- By default the arrows only move focus, so a panel that is slow to show is not opened on the way
  past. Set `activateOnFocus` on the list to pick as they move.
- Name the list with `aria-label` or `aria-labelledby`, and a tab with only an icon with `aria-label`.
- The panel is reachable with Tab, so a keyboard can scroll it. If it starts with something
  focusable, give it `tabIndex={-1}` for one stop less.
- With `defaultValue` left out, the first enabled tab is picked once the page runs, so the server's
  HTML has no panel.
- In forced colors, the active tab is filled with `Highlight` behind `HighlightText`, and the well
  keeps a visible edge. Right to left, the first tab and its key sit on the right.

## Theming [#theming]

Tabs read these theme tokens. Set them on the root, on one part, or on an element around it.

<Tokens />

| Theme token | Purpose |
| --- | --- |
| `--ow-fg` | The well's 6% tint, the active and hovered labels, and the panel's text |
| `--ow-muted` | Other labels |
| `--ow-accent`, `--ow-raised-bg` | The indicator: a 14% accent tint over the raised color |
| `--ow-hover` | The hover highlight (Glide) |
| `--ow-focus` | The focus ring, drawn inside the tab |
| `--ow-radius` | The well's corners; the tabs, the indicator, and the highlight take it less the 4px padding |

<ForMode mode="isolated">

In isolated mode the values sit on each part, so set yours on the part with a class.

</ForMode>

Plain CSS on a `className` beats the component's own rules without `!important`. The list fits its
content, so a full-width row with equal tabs is two rules, and the indicator follows:

```css
.equal-tabs .ow-tabs__list {
  inline-size: 100%;
}

.equal-tabs .ow-tabs__tab {
  flex: 1;
}
```

Sizes are in `em`, so `font-size` on the list scales the tabs. The panel has no padding or margin to
undo; a `display` of your own on it would beat the `hidden` attribute that hides it, so put your grid
or flex on a child.

## Motion [#motion]

The indicator slides on the Core travel spring and stretches from its leading edge, then settles on
the settle spring without bouncing; Glide lights the hovered tab. Press and hold a tab and it scales
to 0.97, the indicator with it if that tab is the active one. A list wider than its parent scrolls
without a scrollbar, and the indicator travels with its tab. All of it follows `--ow-motion-scale`.
With `prefers-reduced-motion`, the indicator moves at once and a held tab dims instead of scaling.
