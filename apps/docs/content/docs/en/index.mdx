OwsemUI provides React components in two families, Base and Owsem, built on
[Base UI](https://base-ui.com). Use them from the npm package or copy them into your project.

## Installation

Requires React 18.2 or 19.

```sh
pnpm add owsem-ui
```

Load the CSS once in your app entry, then import components from their family:

```tsx
import "owsem-ui/styles.css";
import { Separator } from "owsem-ui/base";
```

`styles.css` holds the tokens and every component's CSS. To load only what you use, import
`owsem-ui/tokens.css` plus `owsem-ui/css/<component>.css`.

## Global setup

Base UI asks for two global styles: `isolation: isolate` on your app's root element, so portaled
popups appear above the page, and `position: relative` on `body` for backdrops in iOS Safari 26 and
later.

```css
.root {
  isolation: isolate;
}

body {
  position: relative;
}
```

## Themes

Without a `data-theme` attribute, the theme follows the system setting (`prefers-color-scheme`).
Set `data-theme="light"` or `data-theme="dark"` on `<html>` or any element to force a theme for
that subtree. Every color is an `--ow-*` token you can override; [Theming](/en/docs/theming) covers
switching themes without a flash, recoloring, and the theme tokens.

## Tailwind CSS v4

OwsemUI needs no Tailwind, but works with it. Import `owsem-ui/tailwind.css` first in your global
CSS, before Tailwind, and load OwsemUI's CSS from the same file rather than from JavaScript:

```css
@import "owsem-ui/tailwind.css";
@import "tailwindcss";
@import "owsem-ui/styles.css";
```

`tailwind.css` starts with the layer order, `@layer theme, base, owsem, components, utilities;`.
The first stylesheet that names a layer fixes its place, so OwsemUI's CSS lands above Tailwind's
preflight and below its utilities: a utility in `className` beats the component's own CSS. Keep the
file first; imported after `tailwindcss`, it comes too late. From the registry, import
`lib/owsem/tailwind.css` and `lib/owsem/tokens.css` by their relative paths in the same places.

The same file turns the theme tokens into Tailwind theme values, for utilities such as these:

```tsx
<div className="bg-ow-panel text-ow-muted border-ow-line rounded-ow shadow-ow-raised" />
```

| Utilities | From the tokens |
| --- | --- |
| Colors: `bg-ow-*`, `text-ow-*`, `border-ow-*`, and the other color utilities | `bg`, `fg`, `muted`, `accent`, `on-accent`, `focus`, `line`, `edge`, `hover`, `good`, `warning`, `critical`, `critical-solid`, `on-critical`, `panel`, `raised`, `well`, `pressed`, `line-dark`, `line-light`, `tooltip`, `tooltip-fg`, `backdrop` |
| `shadow-ow-*` | `panel`, `popup`, `raised`, `well`, `pressed`, `primary` |
| `rounded-ow` | `--ow-radius` |
| `ease-ow-*` | `out`, `in-out`, `drawer`, `spring-travel`, `spring-settle`, `spring-glide` |

The utilities read the `--ow-*` tokens where they are used, so `data-theme` and tokens set on an
element still apply. A spring easing pairs with its duration, which has no utility of its own:
`ease-ow-spring-glide duration-(--ow-spring-glide-duration)`.

Every part takes `className` as a string; parts built on Base UI also take a function of their
state. States are data attributes, and Tailwind v4 turns them into variants with no plugin, such as
`data-highlighted:`, `data-pressed:`, or `data-[size=sm]:`:

```tsx
<Separator className="data-[orientation=vertical]:mx-2" />
<Separator className={(state) => (state.orientation === "vertical" ? "mx-2" : "my-4")} />
<TreeRailNav.Toggle className="data-panel-open:text-ow-accent">Settings</TreeRailNav.Toggle>
```

OwsemUI adds its own class to yours and needs no `cn()`: your utilities win by the layer order, not
by merging classes. If your project has a `cn()` helper, it works in `className` as anywhere else,
also inside the function:

```tsx
<Separator className={cn("my-4", inset && "mx-4")} />
<Separator className={(state) => cn("my-4", state.orientation === "vertical" && "mx-2")} />
```

Tailwind's `dark:` variant follows the system theme. To make it follow `data-theme` as the tokens
do, with the system theme where no attribute is set, add this variant to your global CSS:

```css
@custom-variant dark {
  &:where([data-theme="dark"], [data-theme="dark"] *):not(
      :where([data-theme="dark"] [data-theme="light"], [data-theme="dark"] [data-theme="light"] *)
    ) {
    @slot;
  }

  @media (prefers-color-scheme: dark) {
    &:where(:not([data-theme="light"], [data-theme="light"] *)) {
      @slot;
    }
  }
}
```

It covers a theme on `<html>` and one theme nested inside it. `tailwind.css` leaves your `dark`
variant as it is.

## Copy into your project

Components are also published as a shadcn registry, so the code becomes yours. Register the
`@owsem` namespace once, then add components:

```sh
npx shadcn registry add @owsem=https://owsem.dev/r/{name}.json
npx shadcn add @owsem/separator
```

Component files go to `components/owsem/`, and tokens to `lib/owsem/tokens.css`. Import
`@/lib/owsem/tokens.css` once in your app's CSS entry. The `owsem` CLI, with your own token prefix
and isolated mode, comes later.

## Base and Owsem

Every component has one type. **Base** components are Base UI's, with OwsemUI's styling and small
improvements: calm, for dashboards. **Owsem** components are OwsemUI's own, beyond Base UI, with
richer motion and effects. Each type has its own entry point:

```tsx
import { Separator } from "owsem-ui/base";
import { TreeRailNav } from "owsem-ui/owsem";
```

The [component page](/en) shows the type of every component, and filters by it.
