Every OwsemUI color is an `--ow-*` token, a CSS custom property. Themes set the token values and
components only read them, so switching themes or recoloring never touches component CSS.

## Light, dark, and system

Without a `data-theme` attribute, tokens follow the system setting (`prefers-color-scheme`) and
update when it changes, with no JavaScript. Set `data-theme="light"` or `data-theme="dark"` on
`<html>` or any element to force a theme for that subtree:

```html
<html data-theme="dark">
  <body>
    <aside data-theme="light">Always light, inside a dark page.</aside>
  </body>
</html>
```

Nesting works both ways: a light panel inside a dark page, or a dark panel inside a light one.
Each theme also sets `color-scheme`, so native controls, scrollbars, and autofill follow it.

## Switching without a flash

To let people pick a theme, store their choice and set `data-theme` from an inline script in
`<head>`. It runs before the first paint, so the page never shows the wrong theme first. Keep
"system" as no attribute at all, so the OS setting keeps working.

```html
<script>
  try {
    const theme = localStorage.getItem("theme");
    if (theme === "light" || theme === "dark") {
      document.documentElement.dataset.theme = theme;
    }
  } catch {}
</script>
```

The `try` keeps the system theme when storage is blocked. Your theme switcher then sets or removes
both the attribute and the stored value:

```ts
function setTheme(theme: "light" | "dark" | "system") {
  const root = document.documentElement;
  if (theme === "system") delete root.dataset.theme;
  else root.dataset.theme = theme;
  try {
    if (theme === "system") localStorage.removeItem("theme");
    else localStorage.setItem("theme", theme);
  } catch {
    // Storage blocked: the theme still applies until the next page load.
  }
}
```

If React renders your `<html>`, as in Next.js, put the script in `<head>` with
`dangerouslySetInnerHTML` and add `suppressHydrationWarning` to `<html>`, since the script sets the
attribute before React hydrates.

## Recoloring

Theme tokens are the only tokens. Components read them directly, with no token of their own, so
one value changes every component that uses it.

| Kind | Examples | Set by |
| --- | --- | --- |
| Semantic | `--ow-bg`, `--ow-fg`, `--ow-muted`, `--ow-line`, `--ow-accent`, `--ow-hover` | Your app, once for all components |
| Material depth | `--ow-panel`, `--ow-raised-bg`, `--ow-line-dark`, `--ow-line-light` | OwsemUI per theme; you may override them |
| Shape and motion | `--ow-radius`, `--ow-motion-scale` | Your app |

Set a theme token on `:root` to recolor every component, or on any element to recolor only what
is inside it:

```css
:root {
  --ow-accent: #c9b8f0;
}

.billing {
  --ow-accent: #9fd8c8;
}
```

Separator reads `--ow-line-dark` and `--ow-line-light`. Tree Rail Nav reads `--ow-fg`,
`--ow-muted`, `--ow-line`, `--ow-bg`, and `--ow-accent` for its trail. Other semantic tokens
take effect as the components that use them arrive.

A token set on `:root` applies to both themes, which suits an accent that reads on either
background. The default `--ow-accent` has a value per theme instead: a deeper lilac on light, a
pale one on dark, so it stands out from both backgrounds. To give a token a value per theme, use
the same selectors as `tokens.css`:

```css
:root,
[data-theme="light"] {
  --ow-accent: #6b55b0;
}

[data-theme="dark"] {
  --ow-accent: #c9b8f0;
}

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --ow-accent: #c9b8f0;
  }
}
```

Material depth tokens are written out for each theme, not derived from other tokens. If you change
neutrals such as `--ow-bg`, set `--ow-line-dark` and `--ow-line-light` for each theme too, so
etched lines stay visible.

## Customizing one component

The same tokens change one component, or one instance of it: set them on the component, or on an
element around it.

```css
/* Every separator in the settings page */
.settings {
  --ow-line-dark: #b9b0d0;
}
```

Values without a token of their own come from the theme tokens: inner corners from `--ow-radius`
(each layer adds its padding), tints from `--ow-fg` or `--ow-accent` with `color-mix()`, and
Glide's highlight from `--ow-hover`. Names that start with `--_` are private and may change.

For anything a token does not cover, style the part itself. Every part takes `className` and
`style`, and states are data attributes, such as `data-orientation`. Your CSS is unlayered, so it
wins over the component's (see below):

```css
.settings .ow-separator[data-orientation="horizontal"] {
  border-block-start-style: dashed;
}
```

Each Lab's Customization section lists the theme tokens the component reads, as for the
[Separator](/en/separator#scene-customization).

## Cascade layers

Tokens live in `@layer owsem.tokens` and component styles in `@layer owsem.components`. Unlayered
CSS always beats layered CSS, so your plain CSS wins with no extra specificity or `!important`. If
your CSS is in layers too, as with Tailwind, the layer order decides: see
[Tailwind CSS v4](/en/docs#tailwind-css-v4).

## Token modes and prefix

Everything above is theme mode, where the token values live once on the page root. Isolated mode
keeps the same tokens but writes their values on each component's root instead:

| | Theme | Isolated |
| --- | --- | --- |
| Token names | `--{prefix}-accent` | `--{prefix}-accent` |
| Values live | On `:root` and each theme, written once | On each component's root, with the component |
| Changing the accent | One line for every component | Per component |
| Best for | An app with one design system | One component with its own theme, or components in an app with another design system |

An isolated component shares no values, so changing one never touches another, and a value set on
a parent does not reach it. Set yours on the component itself:

```css
.settings .ow-separator {
  --acme-line-dark: #b9b0d0;
}
```

The prefix replaces `ow` in every public token name. It starts with a letter, uses lowercase
letters, numbers, and single hyphens between words, and has at most 16 characters. Private names
(`--_*`) and class names (`.ow-*`) keep theirs.

Both choices go in `owsem.json` and are applied by the `owsem` CLI when it copies components into
your project. The CLI is not released yet; until then the npm package and `shadcn add` use theme
mode with <code data-token-literal="">--ow-</code>.
