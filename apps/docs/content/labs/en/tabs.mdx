Tabs show one panel at a time, picked from a row of tabs. The row is a flat well, and a raised key
slides under the active tab, the same look and motion as Toggle Group. You write four parts; the key
and the hover highlight draw themselves. Scroll to start the tour; the stage follows each part.

## The sliding key [#segmented]

This is all it takes:

```tsx
<Tabs.Root defaultValue="overview">
  <Tabs.List aria-label="Project">
    <Tabs.Tab value="overview">Overview</Tabs.Tab>
    <Tabs.Tab value="activity">Activity</Tabs.Tab>
  </Tabs.List>
  <Tabs.Panel value="overview">The project at a glance.</Tabs.Panel>
  <Tabs.Panel value="activity">What happened lately.</Tabs.Panel>
</Tabs.Root>
```

The stage plays it: a pointer picks each tab in turn. The key goes with the travel spring
(`--ow-spring-travel`), taking the new tab's width on the way; the label it leaves dims, and the one
it reaches lights up. The panel changes at once, so two panels never stack. Press and hold a tab and
it scales to 0.97, the key with it if that tab is the active one.

`aria-label` names the list for screen readers; it is the only prop you must add. `defaultValue` is
optional: without it, the first enabled tab is picked once the page runs, but the server's HTML then
has no panel. On the server, the active tab draws its own key, and the sliding one takes over before
the first paint. It never sweeps in: only a change from one tab to another slides.

## When the tabs do not fit [#overflow]

The list is as wide as its tabs and never wider than its parent. Past that it scrolls sideways, with
no scrollbar: a swipe, a trackpad, or Shift and the wheel move it. The stage picks a tab the edge
cuts, scrolls to the end, picks Billing, and comes back.

The key travels with its tab as the list scrolls, since both are inside the scroller. A click on a
tab the edge cuts brings it in, the arrow keys bring in the tab they land on, and so does a page that
opens on a tab past the end. The focus ring is drawn inside the tab, so the list's edge never cuts it.

## Vertical [#vertical]

With `orientation="vertical"` on the root, the list stands beside the panel, the tabs are as wide as
the widest with their labels at the start, and Arrow Down and Arrow Up move between them. Glide
follows the same axis: anywhere along the list, the nearest tab by height is lit, and a click in a
gap goes to it. A list held shorter than its tabs scrolls down instead.

The stage points along the list, then picks a tab.

## Anatomy [#anatomy]

Four parts are yours to write. Inspect (I) outlines each on the stage, and the indicator too; pick a
name, here or on the stage, to see its tokens.

| Part | Element | Notes |
| --- | --- | --- |
| <Part name="Root" /> | `div.ow-tabs` | Base UI's `Tabs.Root`: the list and the panels, 0.75em apart. `data-orientation`, and `data-activation-direction` for your own panel motion. Theme tokens set on it reach every part inside |
| <Part name="List" /> | `div.ow-tabs__list` | Base UI's `Tabs.List`, with `role="tablist"`: the well. `data-orientation`, `data-size`. It draws the indicator and Glide's highlight |
| <Part name="Tab" /> | `button.ow-tabs__tab` | Base UI's `Tabs.Tab`, with `role="tab"` and `aria-selected`. `data-active`, `data-disabled`, `data-orientation`, and `data-held` while held. Its text is wrapped in `span.ow-tabs__label`, so a tab with only an icon is square |
| <Part name="Indicator" /> | `span.ow-tabs__indicator` | Decorative (`aria-hidden`), and not a part you render: the list draws it. `data-visible` while it sits under an active tab, `data-held` while that tab is held |
| <Part name="Panel" /> | `div.ow-tabs__panel` | Base UI's `Tabs.Panel`, with `role="tabpanel"`, labelled by its tab. `data-hidden`, `data-orientation`. It has no padding, so your content decides |

Base UI has a `Tabs.Indicator` of its own, which OwsemUI does not export. It places itself by
`translate`, which falls between pixels at a fractional zoom such as 110%. This one uses the script
Toggle Group's thumb uses: it rests where layout puts the tab, on the same pixels.

Tabs follow the control geometry: their padding comes from `--py` (FR-9), and an icon is the font
size plus 2 px, as far from the edge as from the top. The well adds 3 px on every side, and its
radius is the tabs' radius plus those 3 px, so the corners stay concentric.

## States and variants [#states]

The stage lines up the three sizes, a disabled tab, and a vertical list, in light and dark. A pointer
picks Members in each theme's `md` list, then Activity again.

| Size | Font | Tab | Well |
| --- | --- | --- | --- |
| `sm` | 13 px | 29.25 px | 35.25 px |
| `md` (default) | 14 px | 38.5 px | 44.5 px |
| `lg` | 16 px | 48 px | 54 px |

| State | What marks it |
| --- | --- |
| Active | The key under it, and its label at full strength |
| Hover | Glide's highlight, and its label at full strength |
| Held | It scales to 0.97, with the key if it is the active tab |
| Disabled | A dimmed label; Glide skips it, and pressing it does nothing |
| Keyboard focus | A 2 px ring, inside the tab |

## Keyboard and accessibility [#keyboard]

The list is one tab stop, and its keyboard comes from Base UI:

| Key | Action |
| --- | --- |
| Tab, Shift Tab | Into the list, then on to the panel |
| Arrow Right, Arrow Left | The next or previous tab, reversed right to left. It loops, and scrolls the tab into view |
| Arrow Down, Arrow Up | The same, with `orientation="vertical"` |
| Home, End | The first or last tab |
| Enter, Space | Pick the focused tab |

By default the arrows only move focus, so a panel that is slow to show is not opened on the way past.
Set `activateOnFocus` on the list to pick as they move: the Lab's own code drawer does.

The panel is reachable with Tab, for a keyboard to scroll it. If it starts with something focusable,
give it `tabIndex={-1}` so there is one stop less. Name the list with `aria-label` or
`aria-labelledby`, and a tab with only an icon with `aria-label`.

With `prefers-reduced-motion`, the key moves at once and nothing scales when held; a held key dims
instead. In forced colors (Windows High Contrast), the active tab is filled with `Highlight` behind
`HighlightText`, and the well keeps a visible edge. Right to left, the first tab sits on the right,
and so does its key.

## Customization [#customization]

The stage controls are open: size, orientation, how many tabs, the list's width, content, the arrow
keys, and the colors of the indicator and the well. The CSS for any of these is in its own tab of the
code drawer.

Tabs read these theme tokens; set them on the root, on one part, or on an element around it such as
`.sidebar`.

| Theme token | Purpose |
| --- | --- |
| `--ow-well-bg` | The well |
| `--ow-well-shadow` | The well's faint edge |
| `--ow-raised-bg` | The indicator |
| `--ow-raised-shadow` | Its crisp edge |
| `--ow-fg` | Labels of active and hovered tabs, and the panel's text |
| `--ow-muted` | Other labels |
| `--ow-focus` | The keyboard focus ring |
| `--ow-hover` | The hover highlight (Glide) |
| `--ow-radius` | The tabs', the indicator's, and the highlight's corners; the well adds its 3 px |

<ForMode mode="isolated">

In isolated mode the values sit on each root, so set yours on the root itself, as the stage's CSS
does with `.project-tabs.ow-tabs`.

</ForMode>

Plain CSS on a `className` beats the component's own rules, without `!important`, since they sit in
a layer. The list fits its content, so a full-width row with equal tabs is two rules; the stage has
it on now, and the key follows when the list or its tabs change size:

```css
.project-tabs .ow-tabs__list {
  inline-size: 100%;
}

.project-tabs .ow-tabs__tab {
  flex: 1;
}
```

Sizes are in `em`, so `font-size` on the list scales the tabs, and a tab's padding is its own `--py`
(FR-11). The panel has no padding or margin to undo. A `display` of your own on a panel would beat
the `hidden` attribute that hides it, so put your grid or flex on a child.

Every part takes `render`. A tab can be any node, an icon with text included, and a link where the
router owns the URL:

```tsx
<Tabs.Tab value="docs" nativeButton={false} render={<a href="/docs" />}>
  <BookOpen />
  Docs
</Tabs.Tab>
```

The motion comes from Core: `--ow-spring-travel` for the slide, `--ow-spring-settle` for the release,
and `--ow-motion-scale` for how far a press goes (0 turns it off).

## Ship it [#ship]

The code drawer writes the component exactly as the stage is set up. Change anything and the lines
that moved light up.

| Part | Prop | Type | Default |
| --- | --- | --- | --- |
| Root | `value` | `any` | |
| Root | `defaultValue` | `any` | The first enabled tab |
| Root | `onValueChange` | `(value, eventDetails) => void` | |
| Root | `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` |
| List | `size` | `"sm" \| "md" \| "lg"` | `"md"` |
| List | `activateOnFocus` | `boolean` | `false` |
| List | `loopFocus` | `boolean` | `true` |
| Tab | `value` | `any` | |
| Tab | `disabled` | `boolean` | `false` |
| Tab | `nativeButton` | `boolean` | `true` |
| Panel | `value` | `any` | |
| Panel | `keepMounted` | `boolean` | `false` |

`size` is OwsemUI's; every other prop passes through to Base UI as it is. Each part also takes
`className`, `style`, and `render`, and its ref goes to the element it renders.

Import from `owsem-ui/base`. In the registry, the item is `tabs`.
